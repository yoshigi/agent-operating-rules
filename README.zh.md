# Agent Operating Rules（中文對照）

> 這是給**人**用的、與 AI agent 共事的規則，不是 SDK、也不是執行框架。（廠商把「harness」用來指把模型變成 agent 的執行環境；這個 repo 是架在任何執行環境之上、人這一側的工作紀律。）門檻是照一個人的工作量校準的，重用任何數字前先讀下面的核心主張。

> 本檔是 `README.md` 的中文對照。內容逐段對應英文版，不增刪主張。

一個人在數月的日常使用中校準出來的一小組規則，用來把工作交給 AI agent：主對話什麼時候必須把工作交出去、交給哪一級能力的模型、派工 prompt 必須包含什麼、產出怎麼驗證，以及這些規則本身允許怎麼改。

---

## 核心主張（讀任何東西之前先讀這段）

**這是一個人在一個環境裡校準出來的系統。可攜的是方法：判準長什麼樣子、驗證的結構、一條規則值得寫下來的那個時刻。常數不可攜。**

這些檔案裡的每一個數字（三個檔案、三百行、三十行回報、二十條教訓、兩次重試）都是針對一種工作量、一套工具鏈、一個人對打斷的容忍度所跑出來的校準結果。這些數字證明「門檻存在，而且值得找出來」；它們不證明「這個門檻就是你的門檻」。（這些是規則用的門檻——派工觸發點、回報上限、教訓紀錄的收斂點、重試次數——不是這個 repo 裡東西的數量；`lessons.md` 收的是十一個案例。）

正確的用法是在你自己的環境裡跑同一套方法，得出你自己的常數：

1. 先不設規則做事，看它在哪裡出錯。
2. 找出錯誤發生**之前**就已經出現的訊號。
3. 把規則寫成「觸發訊號 → 動作」，附一個正例、一個反例，都取自你實際遇到的事。
4. 門檻設在你的證據指向的地方，不是這個 repo 指向的地方。
5. 等同一類失敗發生第二次，再把備忘升格為規則。

照抄這些檔案，等於把別人的門檻套在你的工作量上。這比沒有規則更糟，因為規則會誤觸發，而誤觸發的規則會教人繞過規則手冊。

## 裡面有什麼

| 檔案 | 涵蓋內容 |
|------|----------|
| `model-dispatch.md` | 主對話什麼時候必須派工、哪一級接手、回報契約、升級、驗證、成本直覺 |
| `judgment-rubrics.md` | 五個不可靠模型也能執行的決策判準：該升級、算完成、該問人、該換路、品質底線；外加一段誠實條款，說明這些都修不了什麼 |
| `delegation.md` | 五種 prompt 模板（搜尋、建置、重構、研究、審查），以及讓派工失敗的錯誤 |
| `governance.md` | 規則本身怎麼改：權限分級、治理檔紅線、四步修改法、修剪門檻，以及這類系統死掉的四種方式 |
| `lessons.md` | 十一個產生這些規則的具體失敗。當證據讀，不當指令讀 |

先讀 `model-dispatch.md`，那是你每天會用到的檔。`governance.md` 是之後才會用到、但不能沒有的檔：規則會累積，累積本身沒問題，讓這類系統爛掉的是「累積了卻沒有收納規則」。`governance.md` 就是那條收納規則。

## 模型分級

這些檔案從不點名廠商或模型。它們用三個等級，你自己對應到手上有的東西：

| 等級 | 用途 |
|------|------|
| **機械級** | 格式檢查、清單比對、把已定義的模式大量套用、單檔摘要 |
| **標準級** | 預設。實作、萃取、網頁研究、一般審查、掃描 |
| **高判斷級** | 困難除錯、跨檔架構、第二意見、對抗式審查、高風險決定 |

底層模型一換，等級邊界就會移動。不會移動的那條規則是：**每次派工都明確決定等級，絕不預設繼承。** 繼承的結果是貴的模型做瑣事、便宜的模型做要緊事，而你幾週後才發現。

## 這不是什麼

- 不是框架。沒有東西要安裝，沒有程式要跑。
- 沒有 benchmark。這裡沒有任何東西對照過控制組。這是一個操作者的田野筆記，失敗都還附在上面。
- 不穩定。大約一半的規則存在，是因為某個工具在某個時候表現出某種行為；工具一改，規則就該刪掉，不該出於敬意保留。
- 不完整。`judgment-rubrics.md` 結尾明列了這套方法修不了的事：模稜兩可的請求、品味問題。那些依設計交還給人。

## 大概真的能移植的少數幾件事

如果碰到你的環境後什麼都活不下來，這幾條或許可以：

- **指揮官不下場做事。** 不管你的 context 預算多大，主對話不需要的細節就永遠不該進來。
- **做事的人不驗證自己做的事。** 驗證交給一個不記得東西是怎麼做出來的審查者。
- **指令成功結束，不代表任何事真的發生了。** 任何寫進外部系統的東西，都要有一次獨立的讀回確認。
- **第二次發生才立法，第一次不立。** 一次事件產生一條備忘；重複發生才產生一條規則。否則規則手冊長得比任何人讀得快，而沒人讀的規則手冊等於沒有規則手冊。
- **只說「該做什麼」的規則會被用猜的執行。** 可用的指令是行為，加上理由，加上一個具體的反例。

注意這五條全是結構性的，沒有一條含數字。這就是「什麼能帶走、什麼帶不走」真正的分界線。

## 來源與誠實

這些規則萃取自一個私人的操作 repo，改寫成可公開閱讀的版本。名字、路徑、專案識別、日期、廠商、數字都已移除或降為數量級。例子都是真實事件，抽象到可以發表的程度；例子選擇抽象化而不是刪除，因為沒有例子的判準只是口號；如果抽象化會毀掉例子的意義，那條規則就整條不收。

有些最鋒利的材料刻意缺席：安全性覆核程序與環境的已知死路，兩者都太暴露某一台特定機器，無法發表，而且對你也不會有用。這跟核心主張講的是同一件事，只是換了個形式。

**承認某些東西無法推廣，比宣稱它放諸四海皆準更可信。** 這裡值得信任的是推理。不值得信任的是數字。
